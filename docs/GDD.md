# ほしめぐり（仮題）企画書

## 概要

| 項目 | 内容 |
|---|---|
| ジャンル | 3D 探索アドベンチャー（のんびり系） |
| 視点 | 三人称 |
| 対象 | Android の Chrome（PWA）。PC のブラウザでも遊べる |
| 通信 | なし。完全オフラインで動く（外部 API 不使用） |
| 1回のプレイ | 5〜15 分で 1 つの星を遊び切れる長さ |

『星の王子さま』やマリオギャラクシーのような、歩いて一周できる小さな星をヒロインと一緒に巡る。

## ヒロイン：ミラ

- 宇宙船の航法AI。ホログラムの体を与えられたばかり。
- 惑星のデータは全部知っているのに、実際に**体験したことは一度もない**。
- 口癖は「データでは知ってた。でも……」。知識と体験のずれに驚き、喜ぶ。
- テーマは「知っていること」と「体験すること」の違い。ルールベースのAIであることを、キャラクターの個性として活かす。

### ミラの体（ホログラム）

ミラの体は、プレイヤーの腕輪型の投影機から映し出されている。この制約を、遊びと物語の両方に使う。

- **投影範囲**：腕輪から一定の距離までしか体を出せない（距離は M2 で調整する）。ミラがついてくる理由になり、「あそこに連れて行って」というお願いを遊びにできる。範囲の端に近づくと体にノイズが走り、離れすぎると腕輪のそばに映し直される。
- **触れない体**：最初は物をすり抜ける。スキャンする・光で照らす・狭い所に入るのはミラ、押す・運ぶ・登るのはプレイヤー、という分担で協力して仕掛けを解く。
- **硬い光**：星のかけらで投影機を強化すると、少しずつ物に触れられるようになる。

| 段階 | ミラにできること |
|---|---|
| 0 | 物をすり抜ける。照らす・スキャンするだけ |
| 1 | 花など軽い物を持てる |
| 2 | 地面に足跡が残る。水面に波紋が立つ |
| 3 | 物を押せる。仕掛けを動かせる |
| 4 | プレイヤーの手に触れる（機械の廃墟星。物語の山場） |

- 最後の星で、ミラは初めてプレイヤーの手に触れる。「データでは知ってた。でも……」が一番効く場面にする。クリア後は手をつないで歩けるようになる。
- すり抜けても不自然ではない設定なので、追従（M2）では障害物をよける処理を後回しにできる。

## 基本の流れ

1. 船の部屋で過ごし、星図で次の星を選んでワープする。
2. 小惑星に着陸し、丸い地表を歩いて探索する（ミラがついてくる）。
3. 物を見つけたり、仕掛けを解いたり、写真を撮ったりすると、ミラが反応して覚えておく。データでしか知らなかったことを実際に体験すると、図鑑の項目が「体験」に変わる。
4. 星を出るとき、ミラがその星での出来事を日記に書く。おみやげを 1 つ船に持ち帰れる。
5. 集めた「星のかけら」で船と投影機を強化し、次の星域へ進む。投影機が強くなるほど、ミラは物に触れられるようになる。
6. 旅の記録が増えるほど、ミラの言動が変わっていく。

## 操作（Android 基準）

- 画面左側：仮想スティックで移動。
- 画面右側：ドラッグでカメラを回す。ボタンでジャンプ・話しかける・調べる。
- 画面は横向きを基本とする。
- PC ではキーボード（WASD・Space）とマウスで同じ操作ができる。

## ミラのAI（外部 API なしで「AIらしさ」を作る）

| 仕組み | 内容 |
|---|---|
| 条件で選ぶ会話 | 「今いる星」「好感度」「初めての夜」などの事実を集め、最も細かく条件が一致したセリフを選ぶ（Valve『Left 4 Dead』の会話システム方式）。セリフとルールは `src/data` の JSON で管理する |
| 記憶 | 「初めて海を見た」「溶岩に落ちた」などの出来事を記録し、あとの会話で話題にする。セーブデータに保存する |
| 日記 | 星を出るとき、その星での記憶（落ちた回数、撮った写真、放っておかれた時間など）から日記を書く。文の部品を条件で選んで組み合わせる（Tracery 方式の文法展開）。例：「今日、キミは溶岩に 3 回落ちた。3 回目は、少しわざとだったと思う。」。部品と文法は `src/data` の JSON に置く |
| 現実の時刻 | 端末の時計と、セーブに残した前回のプレイ日時を会話の条件に加える。深夜なら「もう 2 時だよ？」、久しぶりなら「32 日ぶり……」と反応する。時計が前回より過去に戻っていたら、久しぶりの反応はしない |
| 感情 | 喜び・好奇心・不安・信頼の 4 つの数値。時間とともに落ち着く。表情（VRM の表情）、歩く速さ、セリフ選び、声と音楽に反映する |
| 自律行動 | 「プレイヤーについていく」「気になる物を見に行く」「放っておかれたら座る」「怖い物から隠れる」などの行動に点数を付け、一番高いものを選ぶ（ユーティリティAI） |
| 視線と仕草 | プレイヤーや珍しい物を目で追う。まばたきや呼吸の揺れを入れる |
| 声 | 文字に合わせて鳴る「ピポパ音声」。Web Audio で合成し、録音した声や音声合成は使わない。感情によって音の高さ・速さ・抑揚が変わる |

## 図鑑：データと体験

ミラの「知っている」と「体験した」の違いを、そのまま集める要素にする。

- ミラは各星の事実を最初から知っている。図鑑には灰色の「データ」として並ぶ。
- その場で見る・触れる・過ごすと「体験」に変わり、項目に色がつき、ミラの感想が加わる。
  - 例：データ「表面温度 -40℃」→ 体験「寒いって、数字じゃなかった」
- データにない発見（「データにない花がある」など）は珍しい項目として扱い、ミラが一番喜ぶ。
- 見つけた植物や生き物の解説もここに載る。項目と感想は `src/data` の JSON に置く。

## 船（拠点）

星と星のあいだに戻ってくる場所。星図を開く、日記を読む、ミラと話すのもここで行う。

- **おみやげ**：星ごとに 1 つ持ち帰れる。置き場所はミラが決め、ときどき眺めては思い出を話す。フォトモードで撮った写真も壁に飾れる。
- **ミラの夢**：船で休むと、ミラが夢を見る。これまでの星で見た物や出来事（記憶）を組み合わせた「夢の星」が自動で作られ、短い時間だけ歩ける。起きたあと、ミラが夢の話をする。

## その他の要素

- **フォトモード**：ミラがポーズを取り、撮った写真が「旅のアルバム」になる（端末内に保存）。
- **音楽**：Web Audio で合成する。星ごとに音階や音色を変え、ミラの感情によってテンポや明るさが変わる。音楽ファイルを同梱しないので、容量とライセンスの心配が減る。
- **セーブ**：端末内（localStorage / IndexedDB）に保存する。

## 見た目の方針

- トゥーン調・パステル寄りの色。ポリゴンは少なめで、スマホでも軽く描ける表現にする。
- ミラのモデルは VRoid Studio で自作した VRM を使う。それまでは仮モデルで進める。

## やらないこと

- 外部サービスとの通信（ランキング、クラウドセーブ、生成AI など）。
- ブラウザの音声認識・音声読み上げ。Chrome の `SpeechRecognition` は音声をサーバーに送り、`speechSynthesis` も声によってはネットワーク経由で処理されるため。
- 実行ファイル（exe）や APK の配布。ブラウザと PWA で十分とする。
